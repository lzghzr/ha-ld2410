# 杰理固件功能移植

用于 AC632N、AC635N 及相近杰理雷达固件的二进制功能移植：在已验证的 UFW 包中加入协议、蓝牙广播、状态控制或持久化功能，构建尾部代码，重封装 OTA 包，并给出可复核的静态与实机验证结果。只在用户要修改固件功能或评估同系列固件移植性时使用；单纯把现成 `update.ufw` 封装进原厂包时使用 `ld2401-ufw-transplant`。

技能目录自带只读的 UFW/JLFS 检查和安全解包脚本；工具链、下载器和大型 SDK 的取得方式见 [references/toolchain-and-downloads.md](references/toolchain-and-downloads.md)。

## 工作约束

- 先保留原厂启动、升级密钥、校验和原有命令行为。除非需求明确要求，保留手册外命令和原厂 OTA 分支。
- 以目标包自己的芯片、映射、VM/PRCT/BTIF/EXIF 和双镜像布局为准。绝对地址、寄存器约定、版本字段和 VM 起点都必须重新核对，不能从另一型号直接照搬。
- 新逻辑优先放在应用末尾的专用代码区；只在有完整容量算术、边界和迁移方案时移动 VM。每个补丁点记录原始字节、目标地址、跳转范围和返回约定。
- 不能直接调用 `cc1`；使用工作区或 `C:\JL` 中已经验证的 Q32S 工具链（如 `clang`、`q32s-ld`、`llvm-objdump`）及项目脚本。
- 不自动刷机。生成包和报告后，先让用户在可恢复条件下进行 OTA/串口实测。

## 标准流程

### 1. 确认基线

记录输入 UFW 的绝对路径、SHA-256、固件版本、芯片、所有包条目和镜像类型。解析 JLFS/UFW 封装，确认 app 起始地址、执行上限、VM/PRCT/BTIF/EXIF 起点与长度、Key 数据、每个镜像的 CRC，以及是否存在 type 0/32/33/34 等条目。工作区默认是 `C:\AgentWorkspace\LD24`，杰理工具默认位于 `C:\JL`，实际路径以当前任务为准。

### 2. 建立目标映射

对每一个需要修改的 app 镜像分别反汇编并确认：原始调用点的 preimage、被调用函数的序言、参数寄存器、栈布局、返回值、可用 RAM/Flash 区间和所有交叉引用。先确认目标是主广播、扫描响应、GATT 命令、定时器还是 VM I/O，再选择接入点。对函数入口和补丁点做字节断言，防止基线版本漂移后静默生成错误包。

### 3. 设计状态和协议

在写汇编前确定状态记录、版本号、CRC、并发锁、计数器和断电语义。以加密 BTHome 为例，密钥和单调计数器分离保存；A603 只读出密钥，A604 生成并持久化新密钥，A2 在恢复出厂时旋转密钥后调用原厂默认设置恰好一次。VM 记录应包含 magic、schema、size、key、预留计数范围、高水位计数和 CRC；单帧不写 Flash，重启后跳过已预留范围，耗尽时停止加密广播并等待重新配钥。随机填充可复用目标固件已有例程，但不要宣称经过密码学认证。

### 4. 实现和链接

把新代码放入应用尾部，使用目标包的链接脚本和执行上限；需要扩大上限时同步更新所有镜像。保持原函数的寄存器、栈和尾调用约定，先调用原厂 BLE setter/VM API，再附加新数据。对主广播、扫描响应和连接态刷新分别验证控制器类型掩码与更新时机；广播数据不能假设所有接收端都会解析扫描响应。定时器、命令处理和 VM 访问使用有界锁，锁忙时跳过本轮或返回正常的可重试错误。

### 5. 重封装

以原包的 Key、启动区、非 app 附件和封装顺序为模板，同时重建每个需要更新的镜像；不要只修改一个镜像。重新计算 app CRC、嵌套 CRC 和 UFW/JLFS 校验，保持 VM/PRCT/BTIF/EXIF 结束位置一致。输出固件、构建报告、验证报告、源文件和 SHA-256，文件名只反映最终功能、版本和验证状态。

### 6. 静态与实机验证

至少完成：包解析、双镜像一致性、app/ELF 片段比对、hook preimage、跳转目标序言、执行上限、VM 边界、CRC/Key、广播长度与 AD 结构、协议状态模型。实机按 A603、A604、断电重启、计数器单调性、A2 默认设置、FE/OUT 行为、有人/无人和照度、手机/HA 被动与主动扫描、OTA 回滚路径逐项验证。验证清单见 [references/validation-checklist.md](references/validation-checklist.md)。

## 交付规则

只在交付物中保留最终采用的方案、当前构建输入和必要的审计事实；历史证据若对安全、兼容性或审计有用，放入单独的只读报告，并明确它不是可刷包。生成前后检查技能目录表面，确保只含运行脚本、参考资料和接口配置，清理占位文本及无关文件。

## 跨杰理产品移植

可迁移的是架构模式：尾部代码区、原厂 BLE setter、原厂 VM/随机源、命令分发钩子和可验证的 UFW 重封装流程；不可迁移的是具体绝对地址和未经验证的状态偏移。AC632N 的 LD2401C V2.53、LD2410 V2.44、LD2410B V2.44 可作为结构参考，但仍需逐镜像重定位和实机验证；LD2410B V2.04 需要单独建立映射。AC632N 的 2416、LD2410AA、LD2411/LD2411-S、LD2460、HLK-SW01S 需要各自确认雷达状态和 VM 几何。AC635N 的 LD2412、LD2450、LD2451 先按不同芯片族处理，重新确认工具链、函数 ABI、封装和 VM；ADT6101P、LD6002B 等非标准 `.bin.ufw` 先识别容器格式。

详细的型号分层、判据和移植顺序见 [references/porting-matrix.md](references/porting-matrix.md)。
